# Retro facilitation

**The problem:** Retros produce long lists of what went wrong and nothing changes afterward.

**What it does:** Sets up a pre-read timeline, runs a 60-minute agenda (silent writing, clustering, voting), and ends with two or three specific changes, each with an owner, a date, and a way to tell if it worked. Also turns raw retro notes into that format.

**Use it with:** a project, launch, sprint, or incident to look back on, or notes from a retro already held.

**You get:** an agenda, a pre-read outline, and a short write-up with owned changes.
