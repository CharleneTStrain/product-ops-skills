# Product ops context

**The problem:** Every skill needs the same background about your team, so you end up re-explaining your product, owners, meetings, and tools every time.

**What it does:** Writes that background down once in `.agents/product-ops-context.md` — product, teams and who decides, meeting rhythm, where things live, metric definitions, and how launches work. Every other skill in this library reads it first and only asks for what's missing. Gaps are marked "Not recorded," never guessed.

**Use it with:** team pages, onboarding docs, roadmap exports, meeting notes, or a short conversation.

**You get:** a one-page, versioned context file with a changelog, kept current as your team changes.
