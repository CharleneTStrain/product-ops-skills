# Sprint review summary

**The problem:** Engineering reports in tickets and points. Leadership, sales, and support can't tell what actually changed or whether it affects them.

**What it does:** Sorts sprint work into shipped, done but not released, carried over, dropped, and internal; rewrites each item in plain words; and lists what each other team needs to know or do.

**Use it with:** a sprint board export, completed tickets, a cycle report, or demo notes.

**You get:** a recap anyone can read in under a minute.
