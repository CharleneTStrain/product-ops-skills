# Release notes drafting

**The problem:** Engineering ships work described in ticket language. Customers need to know what changed for them. Someone translates by hand every release, and internal details slip through.

**What it does:** Sorts raw tickets or changelogs into new, improved, and fixed; drops internal-only work; rewrites each item as a plain-language outcome; and flags anything whose customer impact is unclear instead of guessing.

**Use it with:** ticket titles, PR descriptions, a changelog, or sprint notes.

**You get:** publish-ready release notes plus an internal "needs confirmation" list.
